## 1. Цели и границы

### 1.1. Цели

1. До успешной аутентификации игрок не может двигаться, пользоваться предметами, командами и правами; вход под чужим ником не даёт доступа (аудит стр. 232; AC-05, AC-29) [ЗАКРЕПЛЕНО].
2. Bridge — единственный канал сайт → Paper: только исходящий HTTPS, без входящих портов и RCON, только белый список действий ([Bridge, §1](../03-architecture/02-bridge-protocol.md)).
3. Надёжная очередь команд: уникальные идентификаторы, подтверждение подлинности, ограниченные повторы, журнал, таймауты, мониторинг, обработка выключенного сервера, сверка whitelist после перезапуска (аудит стр. 714–725; AC-21, AC-27, AC-28).
4. Недоступный backend не открывает сервер: fail-closed (AC-30; OD-46).

## 2. Акторы и разрешения

| Актор | Права в рамках ТЗ |
|---|---|
| Игрок (в игре, до авторизации) | Только подключение; в limbo — ничего, кроме `/login <пароль>` (единственная разрешённая команда) |
| Игрок (авторизован) | Обычная игра в пределах whitelist |
| Владелец ника (Telegram-сессия) | Подтверждает первый вход в `/dashboard` и последующие входы кнопкой бота со сверкой числа; снимает блокировку пары «ник + источник» кнопкой «Это я»; задаёт игровой пароль в `/dashboard` |
| Bridge (системный) | Вызывает только `/api/bridge/v1/*`; исполняет только белый список; не доверяет неподписанному |
| Backend | Единственный источник подписанных команд |
| `admin` (step-up) | `/admin/bridge`: retry, cancel (критичные — со step-up), ротация и отзыв ключей, ручная сверка |
| `moderator` | Просмотр очереди — по разрешению; ротация ключей, критичные отмены — нет |

Матрица прав — [роли и права](../01-product/03-roles-permissions.md). Подтверждение игрового входа возможно только под сессией, чей `user_id` владеет ником (`minecraft_identities.user_id`); иначе `ERR_NICK_NOT_BOUND`.

### 4.3. Матрица запретов в limbo (AC-29)

Требование: **нет** движения, использования предметов, команд, чата, взаимодействия с миром и контейнерами, получения урона и нанесения урона; инвентарь скрыт; игрок невидим для других и не отображается в списке онлайн сайта ([Bridge, §6.1](../03-architecture/02-bridge-protocol.md)). Полный перечень перехватываемых событий Paper (движение, телепорт, команды, чат, interact, drop, pickup, inventory, damage, хотбар и т.д.) — ОТКРЫТО → OD-23 (определяется при прототипе SP-03 на выбранной версии Paper, OD-22).

### 7.2. Ошибки и деградация

Коды — [Bridge, §8](../03-architecture/02-bridge-protocol.md) (`ERR_SIG_INVALID`, `ERR_TS_SKEW`, `ERR_NONCE_REPLAY`, `ERR_KEY_REVOKED`, `ERR_SERVER_MISMATCH`, `ERR_ACTION_SIG_INVALID`, `ERR_ACTION_EXPIRED`, `ERR_ACTION_TYPE_FORBIDDEN`, `ERR_ARGS_INVALID`, `ERR_LEASE_EXPIRED`, `ERR_ACTION_NOT_LEASED`, `ERR_WHITELIST_APPLY_FAILED`, `ERR_RATE_LIMIT`, `ERR_EVENT_REJECTED`, `ERR_CHALLENGE_EXPIRED`, `ERR_CHALLENGE_ATTEMPTS`, `ERR_NICK_LOCKED`, `ERR_NICK_NOT_BOUND`, `ERR_AUTH_BACKEND_UNAVAILABLE`, `ERR_AUTH_DECISION_INVALID`, `ERR_LOGIN_IN_PROGRESS`, `ERR_NICK_ALREADY_ONLINE`, `ERR_NICK_CASE_MISMATCH`, `ERR_BRIDGE_OUTDATED`, `ERR_PLAYER_ONLINE`, `ERR_ACTION_TIME_INVALID`, `ERR_SERVER_PAUSED`, `ERR_CHALLENGE_NOT_FOUND`, `nick.quarantined`, `nick.archive_required`, `site.read_only`, `data.privileged_write_denied`). Не дублируются.

| Ситуация | Поведение |
|---|---|
| Minecraft выключен | Действия в очереди; сайт отображает ожидание; после запуска применяются; по истечении `expires_at` — `expired` и админ-очередь (AC-21) |
| Backend недоступен или решение входа не прошло проверку подписи | Новые входы: limbo → сообщение → kick (`first_join` — через 5 мин, повторные входы — через 120 с); авторизованные сессии не прерываются; журнал Bridge → `security_events` при восстановлении (AC-30). Ответ 429 из квоты auth недоступностью не считается: Bridge ждёт `Retry-After`, игрок в limbo до таймаута |
| Telegram недоступен | Подтверждение кнопкой невозможно → резерв (игровой пароль), если настроен; иначе вход невозможен (fail-closed) [ПРЕДЛОЖЕНИЕ КОМАНДЫ] |
| Расхождение часов Bridge | > 30 с — предупреждение; > 60 с — `ERR_TS_SKEW`; Bridge корректирует смещение по `server_time` из ответа, проверка NTP и алерт (NFR-OPS-23) |
| Дубликат события | Не ошибка: ответ 200, `duplicate` (AC-32) |
| Bridge устарел | `ERR_BRIDGE_OUTDATED` (HTTP 426) на всех эндпоинтах, кроме `heartbeat`; действия не выдаются; админ видит причину в `/admin/bridge` |
| Игрок в сети при `player.data_archive`, `player.data_migrate` или `player.data_restore` | `ERR_PLAYER_ONLINE`, повтор после `player.kick` и выхода игрока |

| Режим восстановления, `bridge_servers.status = paused` | `POST /auth/join` — подписанный `denied` с `ERR_SERVER_PAUSED` (вход закрыт, fail-closed); lease пуст; уже авторизованные сессии не прерываются |
| Bridge не смог вызвать `/abandon` | Challenge закроется `expired` по TTL (не позже 120 с для повторных входов) и засчитается неотвеченным; Bridge повторяет `/abandon` по `Retry-After` |

### 9.1. Тесты атак (обязательный набор, P0) [ПРЕДЛОЖЕНИЕ КОМАНДЫ]

1. Подмена ника: атакующий подключается под ником владельца; получает код; не может подтвердить без Telegram-сессии владельца (SC-GAME-03).
2. Перебор кода и пароля; проверка блока пары и бюджета на ник, записи `security_events`; сценарий DoS владельца блокировкой (п. 7.3.1).
3. Попытки в limbo: движение, команды, чат, предметы, взаимодействие, контейнеры — все отклонены (SC-GAME-06).
4. Backend отключён при входе: limbo → kick; нет «запомненных» входов (SC-GAME-04).
5. Неподписанная команда, подпись другим ключом, просроченный `expires_at`, чужой `server_id`, тип вне белого списка (SC-OPS-04).
6. Replay HMAC-запроса; запрос вне окна ±60 с; отозванный ключ.
7. Пустой снимок whitelist при непустом списке на сайте (SC-ACC-09).
8. Повторная выдача уже применённого `action_id` (идемпотентность).
9. Premium-ник без проверки сессии Mojang — должен вести себя как offline (SC-GAME-02); premium без фиксации типа при подтверждённом первом входе — тоже как offline (TC-GAME-02d).
10. Подмена ответа решения входа: без подписи, неверная подпись, чужой `nickname`, `uuid`, `server_id`, `challenge_id`, чужой nonce, истёкший `expires_at`, повтор (TC-OPS-04g).
11. Второе подключение под ником с живым pending-challenge и вход сразу после выхода первого соединения; подключение под ником, который уже в сети (TC-GAME-07a, 07b); неверное число и «Это не я» — один выбор (TC-GAME-01c); перебор с пары «ник + источник» и сосед за общим NAT (TC-GAME-07c).
12. Освобождение ника: данные не сбрасываются до повторной выдачи, новый владелец не получает инвентарь, эндер-сундук, приваты и права прежнего (TC-ACC-11d); попытка занять ник в карантине и выдача без архива (TC-ACC-12c, 12d); смена ника переносит данные (TC-ACC-10b).
13. Восстановление БД: сессии отозваны, сайт в read-only, вход в игру закрыт, бан или отзыв из последних суток не воскресает (TC-OPS-01c).
14. Прямой PATCH/INSERT клиентской ролью в `site_role`, `account_status`, `game_identity`, `binding_status`, `applications.status`, `guild_members.rank_id` (TC-OPS-06g); прямой SELECT закрытых колонок под `anon` и `authenticated` (TC-OPS-06h).
15. N ≥ 30 одновременных входов: ни 429, ни fail-closed-кика (TC-GAME-04d).
